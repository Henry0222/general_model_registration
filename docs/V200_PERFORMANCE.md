# 2.0.0 配准性能复核

日期：2026-09-08。范围：本地源码版计算引擎。

## 定位与变更

默认 2.0 会执行 8 次 RANSAC 重启。在同一尺度上，每次重启原本都重新搜索同一对 FPFH 描述子的最近邻。现在每尺度、每方向只搜索一次，再复用匹配索引。默认两个尺度的 RANSAC 特征方向搜索由 13 次降为 4 次；FGR 自身的匹配仍独立执行。

互选过滤使用相同的索引顺序、10% 门槛与小集合回退规则。实现根据当前锁定的 Open3D 0.19.0 [特征匹配源码](https://github.com/isl-org/Open3D/blob/v0.19.0/cpp/open3d/pipelines/registration/Feature.cpp#L159)及 [RANSAC 包装源码](https://github.com/isl-org/Open3D/blob/v0.19.0/cpp/open3d/pipelines/registration/Registration.cpp#L250)核对，并直接与原生 API 对照测试。

复用已准备好的同尺度点云。全局匹配新增逐次进度提示，并记录特征匹配耗时、RANSAC 耗时和方向搜索次数。8 次重启、全部候选分支、采样数量、ICP/共同表面精化迭代、评分和选区保护条件均保留。

## 测量方法

同一台 16 逻辑处理器 Windows 机器，项目 Python 环境、Open3D 0.19.0、NumPy 2.5.1，默认 `AlignmentConfig`，继承原应用的自动线程配置。优化前源码单独保存；每个前后版本在新进程中串行运行，不与测试并发。计时启用相同的 cProfile 探针，从模型读取完成后调用 `register_meshes` 开始，不包括加载、导出和启动耗时。

样例包括：原有 0.05 mm 改变立方体；真实口扫 test10 几何施加已知刚体变换；同一口扫几何加双侧一致的约 65% 面片选区。后两者的变换为 XYZ 弧度 `(0.6, -0.4, 1.2)` 和平移 `(37, -25, 19)` mm；真值只用于调用完成后的位姿验证。它们是控制变换基准，不是两次独立扫描的精度评价。

| 样例 | 优化前 | 优化后 | 耗时减少 |
|---|---:|---:|---:|
| 0.05 mm 改变立方体 | 28.03 s | 21.47 s | 23.4% |
| 真实口扫几何 + 已知刚体变换 | 14.56 s | 12.57 s | 13.7% |
| 同一口扫几何 + 重点面流程 | 51.62 s | 47.35 s | 8.3% |

三组前后均为 success；对应变换矩阵元素的最大绝对差均小于 5e-14。真实口扫控制变换的位姿 RMS 约 2.56e-7 mm，前后保持一致。这是同一几何施加刚体变换后的数值恢复误差，不代表实际口扫精度。


结果仅代表这三项本机单次前后配对测量，不能解释为所有病例的平均提速率。Open3D 的多线程随机搜索可能有运行间差异。选择重点面仍会运行全模型基线、选区加权全局搜索、严格选区搜索和后续局部精化，因此所需时间明显更多。

## 复现材料

工作区 `work/registration_speed_20260908/` 保存此次优化前源码、`probe.py`、六份原始 JSON 及性能 profile；该目录位于父工作区，不随公开源码包分发。在项目 Python 环境中，使用 `probe.py --threads auto --full --case cube|ios|selection --output <文件>`；将 `PYTHONPATH` 分别指向优化前源码目录与当前 `src`，串行对比。

针对性测试覆盖原生互选匹配等价性（随机、重复、低匹配回退、小集合）、搜索复用与跨模型隔离，以及保留刚体恢复精度。既有配准、候选选择及选区/API 测试继续作为回归检查。

验证结果：针对性 16 项通过；完整项目回归 121 项通过（30.13 s）。完整测试使用离屏 Qt 运行，日志保存为 `work/registration_speed_20260908/pytest_full.log`。项目的源码启动环境直接导入当前 `src`，重启源码版即可使用；本轮未重新打包 EXE。
