# 3.0 几何精修与结果复核

3.0 在 2.0 前级之后提供刚体几何后级。桌面界面按用户要求默认“自动选择 · 实验”；公共 API 的 `AlignmentConfig.refinement_mode` 仍默认为 `"baseline"`，以兼容既有集成。`AlignmentConfig.algorithm_version` 保持 `"2.0"`；应用版本与前级算法版本含义不同。

| 界面模式 | API 值 | 主结果与对比 |
|---|---|---|
| 原版配准 · 2.0 | `baseline` | 完整沿用 2.0 计算路径，不运行 A/B |
| A · 局部共同表面 | `A` | 寻找未改变共同表面，保存原版与 A |
| B · 连续表面偏差 | `B` | 平滑法向偏差与刚体位姿联合估计，保存原版与 B |
| A/B 对比（保留原版） | `compare` | 计算 A、B，主结果保持原版 |
| 自动选择 · 实验（界面默认） | `auto` | 用网格几何证据选择原版、A 或 B；只运行需要的分支 |

当原版未通过质量门控，或存在人工选区时，后级跳过并写入原因。精修异常、非刚体输出、候选复核失败会保留原版；失败不被替换成单位矩阵。人工选区继续决定配准目标。重复几何或对称目标可能无法建立唯一局部坐标系，此时也会明确回退。

A/B 改变位姿后必须复核。表面距离改善并不能证明真实位姿更准确。候选会重新评估质量，改变位姿的候选最多标为“警告/低可信度”；未通过门控的候选只作为失败预览。界面默认自动是用户的产品设置选择，并不表示该路线已通过科学默认启用标准；原版保留与失败回退机制继续生效。

## 用法与结果

界面按“模型与输出 / 配准路线 / 结果与数值”分区，高级参数默认折叠。结果表显示每个模型的 RMS、P95 与完整流程耗时；下方数值明细显示所选候选的 RMS、平均距离、中位数、P95 / HD95 与最大距离。单位均为 mm，正常数值保留六位小数，极小非零值以科学记数显示，悬停可看更多有效数字；缺失或非有限值显示 `—`。候选切换直接读取各自结果文件，不重新运行配准。失败候选显示明确提示。

这些统计来自双向采样点的最近表面距离；P95 / HD95 是该实现合并样本距离的 95% 分位数。它们不同于有真值评估的中心误差与角度误差，也不同于前级稳定区域的 P90。真实位姿误差只在独立评估中报告，不在推理中读取真值。

```python
from auto_alignment.integration.core import AlignmentConfig, load_mesh, register_meshes, RegistrationCancelled

target, target_facts = load_mesh("fixed.stl")
source, source_facts = load_mesh("moving.stl")
config = AlignmentConfig(refinement_mode="compare")
result = register_meshes(target, source, target_facts, source_facts, config)
print(result.metrics.refinement)
for name, candidate in result.alternatives:
    print(name, candidate.status, candidate.transformation)
```

`result.transformation` 始终为浮动到固定的 4×4 刚体矩阵。`alternatives` 是 `(名称, RegistrationResult)` 的元组，不包含主结果自身；名称为 `initial`、`A` 或 `B`。比较模式的主结果是 `initial`。`metrics.refinement` 包含请求模式、选中方法、状态、原因、耗时和异常。原版模式该字段为 `None`。公共 API 版本保持 1，新增字段和关键字参数兼容旧调用。

每个候选的 `refinement.selected` 标识当前候选，`run_selected` 记录本次运行采用的主结果。`refinement.elapsed_seconds` 是几何后级耗时，`RegistrationResult.elapsed_seconds` 还包含前级与候选质量复核；网格与色图导出另有成本。

流水线和 GUI 导出 `results.json` 的 `candidate_results` 索引，以及 `candidates/<名称>/` 下的独立结果。每个候选有完整刚体矩阵、STL、色图、连续表面距离统计和质量报告。主结果与失败预览仍沿用原有文件规则。查看结果时可切换候选，分别打开窗口对比。批次日志同时记录前级选择和后级选择，不能把前级评价分数当作后级分数。

`register_meshes`、`run_analysis` 和 `run_analysis_with_target` 新增 `cancel` 回调；返回真时抛出 `RegistrationCancelled`。GUI 的“取消并停止”会在阶段边界和精修迭代间响应，不会强制终止线程；单次原生库计算结束前可能仍需等待。取消单独记录，不计为配准失败。调用方进度回调抛出的错误继续向上传递。

## 算法与验证范围

A 使用固定的 192 个局部区域、每区 16 个点、9 个最终候选；B 使用固定的 17 维平滑法向场和 40 次迭代。B 的偏差场只用于估计，输出模型始终只做刚体变换。当前集成不包含 RL 模型。后级接口只接受网格、初始矩阵、模式和进度回调，不读取文件、真值矩阵、真实对应关系、稳定标签或生成信息。

2026-09-15 封存原型的困难样本面板中，A 固定路线为 381/402，B 为 65/134；实验性自动路线为 440/536。B 的 17 个构造失败保留在分母中。自动路线还失去 6 个固定 A 成功例。在正确初值检查中，主面板由 519/536 降到 467/536，用户小面板由 26/26 降到 12/26。这些退化是继续保留原版、实验提示与结果复核的直接依据。

以上属于已封存研究面板，不能视为 3.0 产品端到端成功率：产品还执行前级质量检查、人工选区保护与候选质量复核，来源也缺少外部盲测。严格研究成功条件为中心误差 `<0.01 mm` 且角度误差 `<0.05°`；产品表面距离指标不能代替该真值条件。本轮移植的矩阵复核、默认兼容和回归结果另见 `V300_VALIDATION.md`。

## 耗时与环境

原版模式不计算 A/B。A 或 B 只计算指定后级；比较模式同时计算两条路线，还需导出其他候选的网格和色图。自动模式按证据按需运行，但可能达到 A+B 的耗时。

已封存原型的 10 例新进程测试中，加载加前级平均 29.30 秒，自动路由平均总计 36.93 秒（增加 7.63 秒、26.0%）。这只是该机器与小面板的参考值，不含本次 GUI 的多候选导出成本，不能作为每个模型的耗时保证。工程验证期间的并行校验耗时也不能直接用于用户性能估算。

本轮在其他计算全部结束后，对两例预先选定的大网格串行测量完整产品流程，包含加载、前级、几何后级、候选质量复核及全部导出。原版与 auto 分别为 49.13 → 91.54 秒（+86.3%）和 42.94 → 70.44 秒（+64.1%）。两例采用相反模式顺序，文件缓存已热，排除 Python 启动；仅作为本机使用成本示例。测量范围与证据标识见 [验证记录](V300_VALIDATION.md)。

本轮运行与分发配置统一使用已验证的 Python 3.12，新增 SciPy 1.18.1；NumPy、Open3D、PySide6 按 `pyproject.toml` 安装。源码可直接运行，不需要研究目录或训练缓存。本版本尚未构建或发布 EXE。
