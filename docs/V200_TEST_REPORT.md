生成时间：2026-09-06T00:36:31+08:00。测试目录沿用启动本轮任务时的日期 `v200_20260905`。

**评价口径更新（2026-09-06）：有金标准时以三轴平移、三轴旋转和完整矩阵为主。** 见 [六自由度主报告](<E:/MyScript/Auto_alignment/general_model_registration/docs/V200_MATRIX_REPORT.md>)。下文 P95 保留为辅助，涉及 Wrap 优劣的 P95 结论不能替代逐项平移/旋转判断。

已在原通用软件目录完成 2.0.0 源码改造，未构建 EXE，未修改输入 STL。配准、测试、结果导出和启动诊断均已实际执行。下颌软件的固定工作流没有改造。

本版明显改善了部分共同表面案例的自动定位及末级退化。按辅助点位移 P95，0903 四组中一组低于已保存的 Wrap 结果，另外三组更高；按总旋转误差，2.0 四组都较小，而按固定原点残余平移模长仍有三组较大。不能用单项指标或 success 状态替代完整真值评价。

## 本轮实现

- 保存全局、短 ICP、多尺度各级、共同表面精化和 GICP 姿态；按同一固定采样、固定分母和多尺度曲面评价选择，未改善的精化保留父姿态。
- 两个特征尺度、PCA 合法轴排列与平面方向候选；每条入围分支分别寻找共同表面，再综合选择。
- 加入完整欧氏最近曲面距离、法向兼容性、空间分布和六自由度可观测性。色图不再把开放边界的切向偏差画成零。
- 保留面片身份及重心坐标；在一次配准内复用采样、特征及两个曲面查询场景。修复 PCA 反射基、平移门控受原点影响、噪声估计重纳入已排除点的问题。
- 主窗口与数值引擎分离，首次配准由后台线程加载引擎；警告结果不再写成无条件通过质量判定。

这里的“共同表面”是算法推断的几何支持，不能作为已知物理不变性的证明。几何基元目前实现了平面方向候选；没有宣称实现圆柱/曲率约束、TEASER++、GNC 或有全局最优保证的算法。

## 测试方法与可比性

共 18 对模型：13 对具有已知刚体运动的立方体、4 对无金标准数据、1 对附有既往配准参考矩阵的数据。固定模型与浮动模型路径均写入原始 JSON。全部使用未人工选区的默认 2.0 配置。

基线是本轮修改前保存的本地 1.4.2 源码快照，含此前未发布的稳定区改动；不是重新运行已发行的 1.4.2 EXE，也不等同于此前对话中其他参数/代码版本的结果。基线和 2.0 使用相同 Python 环境与输入。并行计算环境变量设为 4；部分测试进程并行执行，配准耗时只能作运行记录，不能据此声称算法加速倍数。

已知运动采用项目已核对的矩阵约定：`p_moving = R_xyz @ (p_fixed + t)`，其中 `R_xyz = Rx @ Ry @ Rz`。因此真值配准矩阵为 `[R_xyz.T, -t]`。0829 使用平移 (30, -40, 15) mm、旋转 (8, 168, 285)°；0903 使用用户补充的 (100, -60, 500) mm、(58, 47, 268)°。

在固定模型上固定采样 20,000 点，计算 `Δ = T_result @ inverse(T_gold)` 作用后的对应点位移；表中的 P95 为这些位移的 95 分位数，单位 mm，越小越好。它不是最近表面距离、ICP RMSE 或软件内部 P90。近 1e-6 mm 的数值表示合成 STL 的数值一致性，不是扫描仪具有纳米级测量精度。

已知矩阵仅在配准返回后参与离线评价，不传入引擎。第一轮暴露的重划网格退化用于改进第二轮固定评分，因此此数据集是开发/校准集，不能冒充独立盲测。最终算法冻结后另有一个非立方体、局部形变、大幅刚体运动的自动化测试通过；这仍不足以替代独立外部数据验证。

## 候选诊断：为何仍未达到 Wrap

| 困难案例 | 实际选择 P95 | 候选池中最低 P95（仅离线诊断） | Wrap P95 |
|---|---:|---:|---:|
| 立方体不充分复杂表面变化0.5 | 3.305113 | 1.960052 | 2.497157 |
| 立方体充分复杂表面变化0.8 | 3.334227 | 2.405867 | 2.683172 |
| 立方体充分简单表面变化0.5 | 0.02419564 | 0.01745397 | 0.06193716 |
| 立方体简单偏移表面变化 | 3.439847 | 2.189234 | 2.564328 |

这四组的候选池里都已有比各自 Wrap 导出更接近真值的姿态，但生产评分没有全部选中。最低真值误差候选包含被拒绝的更新，只用于定位问题；生产软件绝不能读取真值挑选它。下一步重点是区分共同结构与形变偏置的评分和模型选择，而不只是增加迭代次数。

当前的防退化只保证固定内部评价不退化，不保证真值位姿误差不退化。完全/广泛变化的表面会让评分更偏好吸收部分形变的姿态。需要在独立数据上比较稳健损失、区域均衡、几何关系约束与候选稳定性，不能为这四个文件写专用偏置或用试验矩阵选择结果。

## Wrap 对照的证据范围

直接读取用户保存的 Wrap STL，以原始浮动模型与导出模型保留的三角面顶点顺序建立对应，Kabsch 恢复刚体矩阵，然后检查全部三角角点是否符合单一刚体运动。没有使用 ICP 来反推或优化 Wrap 的结果。若包含多个完整壳体，逐壳检查。

0903 四组均通过：对应点重建 RMS 约 1.8e-5 mm。0829 的面1和面3也通过刚体重建；其已保存的无干预 Wrap 结果分别有约 2.11 mm 和 81.09 mm 位姿 P95，后者为近 180° 的对称错位。0829 边变化的角点对应 RMS 为 0.38 mm，未通过刚体验证，所以不报告它的 Wrap 真值误差。

这些是所提供文件的结果，不代表 Wrap 在其他手动操作、初始化或参数下的最好能力。无需得到 Wrap 的内部实现，仍可以客观比较最终位姿；但无法从导出文件推断它采用了哪种内部算法。

## 启动速度：根因、修复与测量

旧导入链：主窗口 → batch → pipeline → registration / comparison → Open3D、NumPy 及其依赖。在窗口创建前加载这些计算模块，是实测中的主要等待来源。

将批次数据结构独立到 batch_models.py，GUI 只导入轻量类型，开始配准后在工作线程中加载 batch。它把必要的首次计算初始化移出了窗口启动路径，不是消除了依赖加载成本。首次打开三维查看器也仍需加载 Open3D。

| 同一方法，三个新 Python 进程 | 改造前 | 2.0 |
|---|---:|---:|
| 窗口显示并处理首轮事件的中位时间 | 1.482670 s | 0.259112 s |
| GUI 模块导入中位时间 | 1.299077 s | 0.098958 s |
| 窗口就绪时已加载 Open3D | 是 | 否 |

窗口就绪时间减少 82.5%，约为原来的 17.5%。测量为同机、源码、新进程、热文件缓存、离屏 Qt；并非人眼计时，也不是冷启动或 EXE 测试。单次早期 importtime 记录约 9.11 s，条件不同，不用它计算优化倍数。

现有 .spec 是 onefile 结构，既有 EXE 约 150 MiB；解包、磁盘缓存及系统扫描可能额外影响启动。此次没有启动、重建或测量 EXE，因此不能把这些可能因素当作已测定的具体耗时。以后打包时可比较 onedir 与 onefile 的冷/热启动，再决定打包形式。
